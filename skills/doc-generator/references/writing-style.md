# Writing Style

Applies to all documents produced by `doc-generator` (Functional, Technical, Test) and is a good default for `session-recorder`'s handoff narrative too.

- Use simple, minimalistic English — avoid jargon where a plain word works.
- Avoid long paragraphs — prefer bullet points.
- Each bullet: roughly 15–25 words. Not a hard limit, but a paragraph-in-a-bullet is a sign to split it.
- **Each section/block: max ~70 words.** If a section needs more than that to explain, it's a sign to split it into two sections or move detail into a diagram instead of more prose.
- When explaining something that happens as a sequence of steps, use a flat bullet list — no sub-headings inside a section for this. Sub-headings are for the document's own section structure (picked via the checkbox list below), not for breaking up a single section's content.
- Prefer an illustration/diagram over a long text block wherever a diagram communicates the same thing faster (process flows, architecture, dependencies) — especially once a section is approaching the 70-word cap and still has more to say.
- Write for a reader picking this up cold — don't assume they were in the conversation.
